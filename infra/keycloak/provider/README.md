# Credential-change session revocation

The provider jar is compiled in `infra/keycloak/Dockerfile` against the exact Keycloak 26.8.1 runtime libraries. Keep both the server image and the JDK builder immutable and pinned. Keycloak currently reports `eventsListener` as an internal SPI; any Keycloak upgrade must rebuild the provider and pass the credential-change acceptance checks before release.

The `trading-community-credential-revocation` listener watches password reset/update, OTP update/removal, email verification/change, and profile update events. It also handles Admin REST password resets, credential deletion (`DELETE` or Keycloak's `ACTION` operation), and every `UPDATE users/{id}` event. Keycloak strips credentials from admin event representations, so any user representation update conservatively revokes all application and online provider sessions for that user. These identity and credential changes revoke the session making the change as well.

Before terminating provider sessions, the listener sends a signed OIDC logout token to every enabled OIDC client with a configured backchannel URL and `trading-community.credential-revocation=true`. The configured relying party accepts subject-only notifications (`backchannel.logout.session.required=false`). This notification is independent of provider or client session records: it contains the frontend realm issuer, the client's audience, the user's public subject, a fresh token id, issue/expiry times, and the standard empty-object backchannel event. It deliberately omits `sid`, so the application revokes every opaque session for that issuer and subject. An application session whose provider SSO session has expired is therefore still revoked, including when no provider sessions remain. Existing provider sessions are then terminated through Keycloak's normal logout path. The current realm uses public subjects; pairwise subject mappers and federated storage adapters must not be enabled without extending and validating subject mapping and credential-change event coverage.

If no application target is designated, any designated target lacks its backchannel URL, a user cannot be resolved, local provider logout does not complete, or an application backchannel endpoint is unavailable or returns anything outside 2xx, the listener marks the current provider transaction rollback-only and fails. Subject-wide requests have bounded connection/response waits, do not follow redirects, and never log logout tokens. Unexpected runtime failures also mark the transaction rollback-only because Keycloak catches event listener exceptions. This prevents credential-change success from being committed while an application session remains valid. Missing listener installation or realm registration blocks local identity setup: `scripts/configure-local-identity.mjs` verifies the listener id and exits with an error otherwise.

The live unavailable-API drill proved rollback by reading the persisted OTP and both app sessions after API restoration. Keycloak nevertheless redirected the native action with HTTP 302 and `kc_action_status=success`; event dispatch catches the listener exception. Do not interpret that redirect as committed success. Provider failure messaging needs rendered UI review before production. The successful online drill separately proved OTP deletion and 401 responses from both orphan-SID app sessions; an Admin REST password reset also revoked both sessions when no provider SSO existed.

The account console removes OTP credentials through the `delete_credential` application-initiated action; Keycloak emits `REMOVE_CREDENTIAL` and `REMOVE_TOTP`, which the listener handles. The Admin REST credential-delete path uses an `ACTION` admin event. Keycloak's `disable-credential-types` operation does not emit an admin event and is not automatically covered. Before an operator uses that operation, they must explicitly log out all user sessions; production runbooks must keep that step as a release gate until a supported event hook exists. The login theme also forces the built-in logout-sessions flag for password and TOTP setup flows. Account-level security operations must continue to emit these Keycloak events or be added to the listener before they are enabled.

Build and configure locally with `docker compose --env-file .env.local up -d --build keycloak`, then `node scripts/configure-local-identity.mjs`. The P04 protocol run uses `pnpm test:p04:live`; its output intentionally omits credentials, codes, cookies, tokens, and action links.
