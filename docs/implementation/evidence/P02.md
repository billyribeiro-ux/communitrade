## Concurrency and failure results

- Twelve simultaneous identical actor/operation/keys executed the callback once, returned the same resource and replayed eleven responses. Reordered object keys replayed; changed input conflicted. Stored responses retain at least 24 hours. Suspension prevents replay and unverified actors cannot issue commands.
- Twenty-four simultaneous creates with a quota of seven produced exactly seven successes. Quota, draft, outbox and idempotency ledger rolled back together on an injected failure. Reservations block additions and settle against their original owner/bucket.
- Two writes with the same revision produced one winner and one stale-version conflict. A foreign owner's private draft and a missing draft both return 404. Input cannot choose a different owner through the request adapter.
- Parallel outbox consumers did not overlap claims. Reclaiming an expired lease incremented its attempt; the stale acknowledgement failed while the current one succeeded. Duplicate domain revisions conflicted and the eighth expired attempt became terminally failed. No actual email/payment/queue dispatch side effect is claimed.
- Runtime request tests reject unknown fields, missing concurrency/CSRF headers, invalid UUIDs/dates/bounds, bad decimal primitives and oversized/invalid chart state. Form and binary content types survive the server adapter. Unknown HTTP exceptions return a redacted problem body with a generated request ID, no-store and safe status mapping; health 503 stays minimal.
- Decimal tests reject unsafe JavaScript numbers, excess precision and overflow. Historical expired option accounting remains deterministic; new entry validation refuses expired contracts. Costs are never silently defaulted to zero. Initial risk stays frozen even if a later state changes.
