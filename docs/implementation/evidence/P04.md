# P04 identity, profiles and private media evidence

Date: October 20, 2026. Requirements: REQ-002, REQ-003, REQ-004, REQ-024, REQ-027. Status: implemented locally; automated application checks, complete live identity/profile/media journey and final subject-wide credential-revocation drill pass. Rendered browser acceptance remains blocked and is not passed.

## Delivered behavior

- Real Keycloak registration, verification, password setup/recovery and MFA through provider-owned pages. Confidential OIDC code flow uses S256 PKCE, signed issuer/audience/time checks, encrypted verifier/nonce, hashed state, distinct per-transaction HttpOnly browser binding and replay refusal. Application storage contains no passwords or provider access/refresh tokens.
- Random opaque application sessions are hashed at rest, rotated on login/step-up, checked on each request and subject to member/staff idle and absolute expiry. Owner session controls, logout-all, verification/onboarding restrictions, strict Origin plus session-bound CSRF and server roles are implemented. Admin shell requires verified MFA; sensitive operations require signed recent assurance. Role/account security changes revoke sessions through additive database triggers.
- Persisted onboarding, declarations and versioned policy acceptance; safe Free/monthly/annual intent survives identity setup. Paid entitlement remains server-derived. Existing Pro entry routes to billing. Preferences, security, sessions and public profile settings use real APIs.
- Circular avatar/initials, display name, bio, interests, member-reported public statistics, month/year join date, profile links, sharing and Ideas/Updates/Reposts sections. Feed data itself remains P08/P09, with honest empty states. Links use `nofollow ugc noopener noreferrer`. Reserved/duplicate handles, optimistic revisions and one handle change per 30 days are enforced. Old handles stay reserved after their one-year redirect expires. Public projections exclude private identity and hidden/private position aggregates; win rate uses wins/(wins+losses), with retrospective and cost exclusions.
- Owner upload intent → raw bytes → completion → transactional outbox → pg-boss worker → processed filesystem object. PNG/JPEG/WebP only; 2 MiB, 40 MP and 10,000 px input bounds; at most 512 px WebP output; metadata stripped. Worker row locking protects against duplicate processing and expiry races. Invalid images reach terminal rejection; transient failures and outbox delivery have bounded retries. Expired/abandoned objects and failed temporary writes are cleaned up.
- A ready avatar is public only while attached to an active profile. Removal immediately denies anonymous reads; quarantine is never served. All image responses are private/no-store. Authored UI remains plain CSS/CSS Modules with Phosphor; no Tailwind was introduced.

## Credential-change enforcement

The application-owned Keycloak event listener is compiled against the pinned server libraries. Password/TOTP changes, email/profile/verification changes, credential removal, Admin REST password resets and conservative root user updates send signed **subject-only** logout directly to every designated application target before terminating provider sessions. This does not rely on an existing provider SID or client-session membership. Each target requires a configured URL; missing targets/URLs, non-2xx responses and unexpected failures mark the credential transaction rollback-only. Signing uses the configured frontend issuer, client audience, fresh jti, short expiry and empty-object standard logout event. Requests have bounded timeouts, no redirects and no token logging.

A separate `pnpm test:p04:credentials` drill passed unavailable-backchannel rollback and revocation of orphan application sessions even when no provider SSO session exists. The Admin REST password reset revoked two app sessions with zero provider SSO. In a fresh pair of sessions, actual account-console OTP deletion with the API stopped preserved the OTP and both sessions; successful deletion after API restoration removed the OTP and made both sessions return 401. The synthetic OTP fixture was restored. Synthetic application-session fixture creation uses the existing server AuthService only in local mode, verifies the active synthetic identity, and captures opaque tokens in the test process without printing them. This fixture setup does not claim another OIDC login; real OIDC is independently covered by the complete live driver above. It never edits the Keycloak database or disables the application backchannel.

Keycloak catches event-listener exceptions: the listener explicitly marks the transaction rollback-only. During the unavailable-API test, the native action still redirected with HTTP 302 and `kc_action_status=success` despite the persisted credential change rolling back. Persisted credentials and session responses establish the security result; the redirect does not. Native account-console error messaging therefore has a known ambiguity that requires provider UI review before production; rendered failure UX is not claimed as verified.

Keycloak upgrades must rebuild and rerun the drill. Pairwise subject mapping and federated storage are unsupported until their subject/event coverage is implemented and validated. The provider's eventless `disable-credential-types` operation is outside automatic coverage; operators must revoke sessions first, and production operation remains gated on that procedure.

## Defects corrected during acceptance

Live transport caught prototype-backed Express headers disappearing during request spreading; explicit request-field preservation plus real Nest HTTP tests fixed profile/media 500s. Other corrections include standard callback parameters, actual registration/password setup sequence, concurrent transaction cookies, preferences projection, avatar URL/cache/polling, policy slugs, stale privilege sessions, profile cooldown/tabs/link attributes and production release flags.

Worker tests caught concurrency/expiry races and an outbox failure path that could delete an already-ready avatar; conditional transitions now protect it. Provider driver regressions cover one-hop callback handling, actual confirmation, error terminals and password/OTP challenge progression. The native TOTP single-use policy is preserved: the drill waits for fresh codes instead of repeatedly submitting a consumed code. A deprecated account API returned 405 and was discarded as evidence. HTTP redirects alone are not treated as successful credential changes or rollback; persisted credentials and app-session access are checked.

Two initial failed test drafts left append-only catalog metadata. Their two `p04-profile-test` instruments are disabled (total 2, enabled 0); integrity triggers were preserved. Current tests reuse immutable catalog fixtures and clean mutable records. No application/identity database or Docker volume was reset.
