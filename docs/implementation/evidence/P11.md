# P11 — Notifications, durable delivery and product measurement

Date: October 20, 2026. Requirements REQ-020, REQ-026 (background delivery/telemetry portion), REQ-031; acceptance AC-020, AC-026, AC-031. Local implementation and automated/connected acceptance are complete. Rendered browser interaction/visual acceptance remains blocked and is not marked passed. P12 billing lifecycle, P13 broader staff/privacy workflows and P14 production/recovery acceptance remain subsequent scope.

## Delivered behavior

- Owner-only inbox aggregation, unread totals, individual/all read state and precise owner/filter-bound cursors. Followed publications, replies, mentions, bookmarked-idea material updates, correction decisions and account notices originate in business transactions. Fanout resolves current recipients/preferences/mutes, suppresses self-notification, rechecks exact public-source rights, and preserves generic activity text without comment bodies or private journal notes. Hidden/unavailable public source IDs and links are removed from owner projections. A publisher's reply still notifies its reply target; distinct security/account events retain separate identities.
- Preferences default optional digest and first-party measurement off. Category flags control in-app activity; followed-publication preferences also govern followed digest content. Essential account/security/billing notices cannot be disabled. Daily digests use 08:00 in the current IANA zone, DST and quiet hours (default 22:00–08:00), one owner/local-date business key, current send-time opt-in/quiet-zone/account/suppression/rights/entitlement checks, and signed expiring POST-confirmed unsubscribe with a no-store/no-referrer/noindex confirmation route. Free gets followed-author ideas; Pro can add five private saved public searches. Searches have atomic concurrent limits, normalized filters, case-insensitive names, revisions and owner isolation; after downgrade existing searches remain readable/removable, while creation/update requires current Pro.
- Transactional outbox and pg-boss use stable business/attempt identities. In-app fanout commits aggregation with acknowledgment atomically. Email has a separate durable ledger, stable Message-ID, five attempts within 24 hours of its first attempt, bounded backoff and queued/stale-claim recovery. Enqueue-before-DB-ack replay preserves its identity and processing budget. SMTP acceptance followed by lost DB acknowledgment and uncertain/stale SMTP claims are quarantined rather than blindly resent. Recipient 550 creates transport suppression; AUTH/configuration failure does not suppress a recipient. Destinations must be a single mailbox. SMTP failure does not roll back published content.
- First-party activation/return/publication/review/report/conversion/churn vocabulary requires current versioned consent, enum-only properties, hashed business keys and owner/event dedupe. Withdrawal serializes against insertion and erases retained owner events; hourly bounded purge removes records older than 90 days. Activation follows the MVP definition: three followed authors/instruments and then trusted publication/comment/journal creation within seven days of joining, once per owner. Onboarding alone does not count. Browser input is restricted to return; trusted conversion/churn integration remains P12. No private thesis/notes/titles/handles/URLs/credentials are analytics properties.
- Staff job pages expose safe status, attempts, failure codes and aggregate backlog/event counts through the API. Current admin role, recent MFA, CSRF, command idempotency, original retry budgets and immutable reasoned audits protect retry actions. Unknown/permanent/uncertain delivery failures and frozen publication/media evidence cannot be reset through a generic retry. Snapshot SDK errors now reduce to safe failure-stage codes before API/queue persistence, preserving diagnostic value without retaining raw signed renderer URLs.

Routes include `/app/notifications`, `/app/settings/preferences` (including saved searches), `/admin/jobs` and `/digest/unsubscribe`. Navigation/dashboard connect the owner inbox. Plain CSS/CSS Modules and Phosphor remain the UI standard. No Tailwind or Phase 2 streaming/scanner/broker/payout behavior was added.

## Repairs and verification limits

Early isolated delivery acceptance exposed a PostgreSQL microsecond-vs-JavaScript millisecond fixture timing race; setting the replay fixture explicitly due fixed it without weakening production due-time checks. Review found and corrected publisher-reply suppression, transactional aggregation that could swallow later security notices, doubled digest origins, Pro follow/search composition, send-time preferences, mailbox validation and consent response fields. A live negative saved-search input was correctly rejected with HTTP 400 rather than its driver's expected 422; the assertion was corrected, not the rejection behavior.

Live acceptance exposed a real capture lifecycle race: React cleanup removed the browser callback while leaving its DOM readiness marker. Setup/cleanup now pairs readiness with an instance-owned callback, publishes only after chart initialization/paint, prevents disposed async initialization from resurrecting readiness, and protects a newer callback from stale cleanup. The worker checks readiness and invokes that callback atomically in one browser call, with a bounded five-second retry for transient remount/readiness loss. Regression tests simulate cleanup/remount, late initialization, transient pending capture and permanent not-ready failure; structured capture results retain safe failure codes. Single-use signed claims remain unchanged. After the final optimized build and production boundary harness, the web service was restarted, its `/health` readiness checked, and P11 followed by P09 trusted captures and all nine local smoke checks passed without intervening builds/source changes. An initial setup probe used the nonexistent `/api/health` path; it failed before live acceptance began and was corrected to `/health`. The isolated renderer's not-found marker and safe claim/script/asset/stage diagnostics make future failures visible without raw browser URLs. Do not run builds/type generation/parallel Next start harnesses during trusted capture. Read-all cutoff also stays entirely in SQL to avoid PostgreSQL/JavaScript timestamp precision loss. Image fixture tests retain the existing nonfatal Fontconfig warning; final assertions passed.

The supported in-app browser attempt to localhost was rejected by a saved user/managed origin permission. No alternate browser, raw CDP or headless UI-inspection workaround was used. Rendered visual, focus/keyboard and interactive UI acceptance remain G08/G12 gates. Product-owned trusted chart capture is exercised by the existing publication workflow; it is not claimed as manual browser inspection.
