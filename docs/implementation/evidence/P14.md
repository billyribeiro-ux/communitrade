# P14 — Integration, recovery and release readiness

Date: October 22, 2026. Implements REQ-025, REQ-026, REQ-027, REQ-028, REQ-030 and REQ-031. This is a local engineering candidate with an explicit **NO_GO** release decision. No deployment, purchase, charge, commercial credential conformance, human legal/design approval or production recovery claim is made. The checkout has no Git metadata/remote; no commit, PR or remote CI result is claimed.

## Implemented scope

- Fixed-origin Vercel/API proxy preserves original request bytes, cookies and no-store responses; signs method, complete path/query, body hash, timestamp, nonce, principal and the provider-overwritten address. Generic forwarding headers cannot select a rate-limit principal. Server rendering has a distinct signed service principal. API replicas atomically consume PostgreSQL replay nonces; missing configuration/storage fails closed. Exact provider/worker endpoints retain their independent signature checks.
- Replaceable private R2 media and export stores use native SigV4, strict keys/endpoints, bounded bytes/deadlines, immutable conditional writes and safe retry handling. Owner/current-public-attachment authorization stays on the server. Quarantine is private; media input is 2 MiB, trusted processed snapshots 4 MiB and exports 50 MiB. No public bucket or bearer download URL is introduced.
- Resend/Svix webhook verification uses exact original bytes, bounded timestamps, configured sender, single-recipient validation and transactional event deduplication. Permanent bounce/complaint suppresses both accounts and keyed addresses, including anonymous support receipts. SMTP checks suppression before transport. Replay records contain no raw body, subject or email; bounded retention clears expired nonces and 30-day webhook metadata.
- Production refuses fixtures/local storage/fake billing, weak/shared keys, insecure transport and missing reviewed operational configuration. Dynamic CSP supplies a fresh document nonce, rejects inbound nonce spoofing and production eval, and blocks frames/objects. CSS Modules/CSS and Phosphor remain the UI standard; rendering-library style attributes remain permitted for geometry. Domain-verified HSTS remains an operator gate.
- Nonroot API/worker images, optimized pinned Keycloak image, Vercel project reference, manual Render Blueprint, separate runtime/migration/queue/identity roles, migration ordering, rollback and independent backup procedures are concrete local artifacts. Safe operational counters expose heartbeat/aged work/uncertain side effects/failed privacy without payloads. CI definitions now include advisory/source review and production-image builds; these have not run remotely.
- Public feed queries page each cursor-correct original/repost branch through the feed index before merging. Card aggregates run on the bounded result. Identical rights checks are reused only within one request; every source/version/profile/mute is checked again after hydration. Tests cover visibility changing during hydration and rights revoked between requests. Page size and authorization were preserved.
- Isolated generated-database recovery/load and role-privilege harnesses execute actual PostgreSQL, application services and worker erasure. API idle-pool errors now emit a fixed safe event instead of crashing/serializing a database client. Local Compose starts the worker directly through Node/tsx with a 30-second grace so SIGTERM drains jobs; restart it explicitly after source edits.

## Recovery and performance measurements

`pnpm test:p14:recovery` passed on uniquely generated source/restore databases with all current migrations. Actual custom-format pg_dump/pg_restore plus a separate synthetic object checkpoint preserved its SHA-256. A newer independent suppression ledger was exported after erasure, imported into the restored database and applied by ordinary worker stages. Restored session authentication was rejected; private journal/object bytes and public derivatives disappeared; personal text was redacted; immutable financial terms and the unrelated owner survived. The newer watermark was absent as expected. Local restore/check elapsed was **650 ms**, between synthetic watermark commits **253 ms**. These tiny-fixture values establish neither production RPO nor RTO. The actual [recovery result](../artifacts/P14/recovery.json) and runbook explain the scope. Real managed DB, identity, objects, independent ledger custody and provider reconciliation remain G09.

The initial eight-connection benchmark exceeded the original pool/latency bounds. Moving aggregates after pagination and reusing full identical rights inputs helped, but another run still missed 750 ms. Cursor-correct branch limits then enabled the existing feed index and passed unchanged thresholds. The [stock baseline](../artifacts/P14/service-load.json) used 5,000 accounts, 1,000 recent valid-session MAU proxies, 100 concurrent authenticated requests, 50,000 publications and 250,000 comments, 40/20/20/10/10 feed/search/chart/private-read/private-write, normal 20-result pages and the API's actual eight-connection pool. Feed/search p95 **315/315 ms**, chart **293 ms**, private read/write **299/251 ms**, pool checkout wait **189 ms**. It is an in-process service/database workload with one stock reference template, no internet/supplier latency and no browser LCP or production capacity claim. The subsequent [mixed-asset result](../artifacts/P14/service-load-mixed.json) uses **20,000 stock, 15,000 futures and 15,000 option trades**, 2,500 per each of six option strategies, 50,000 linked pending positions and 25,000 option legs. Existing seeded rights are checked without adding grants; frozen plans and initial risk use the existing hydrator/calculator. Zero events/outcomes means no fabricated trade results. An initial mixed run measured feed/search p95 427.2/427.4 ms. After making the command enforce the original latency limits and minimum sample counts with a nonzero failure exit, the final run passed: feed **463.6 ms**, search **464.0 ms**, chart **298.3 ms**, authenticated private read/write **302.8/226.2 ms**, session auth **22.9 ms**, pool checkout wait **101.5 ms** and mixed burst **485.9 ms**. This is one warm local service/database burst using unchanged 20-result pages, eight connections and workload proportions; it does not measure HTTP/network latency, supplier retrieval, browser LCP, sustained production capacity or a monthly availability objective. Two early mixed-harness column-alias errors were corrected and generated databases cleaned before these successful runs.

## Repairs and limits

Early failures exposed strict TypeScript body/storage-port mismatches, parser ordering, test fake-auth/projection/fixture fields and production packaging duplicate-copy behavior. These were corrected before the passing suite/builds. The first outage drill exposed the idle pg pool crash; the next exposed signal delivery through the local worker wrapper. Both fixes passed the final drill. A host HTTP attempt used an older host build; rerunning against the current Docker build passed the nonce check. Older HTTP drivers expected obsolete subscription wording and moderator restrictions; assertions now verify current reconciled-provider copy, MFA-gated staff entry and denied administrator API access. Repeated identity/chart runs reached real shared proxy rate buckets; normal window rollover was honored, with no rate reset, spoofed forwarding or limit relaxation. Initial failures are not recorded as passes.

The supported in-app browser rejected `http://localhost:3000` under its saved origin permission. No alternate browser, raw CDP, headless UI inspection or screenshot workaround was used. HTTP/SSR and product-owned trusted publication capture do not establish manual rendered interaction, focus/keyboard, screen-reader, responsive/zoom, real contrast, cross-browser or mobile p75 LCP acceptance. No WCAG certification is claimed. The media library emitted a Fontconfig diagnostic during tests; successful synthetic image assertions do not replace visual typography review.

## Release decision and next work

[The register](../p14-release-status.json) keeps **G01–G12 open** and `pnpm check:p14:release` reports **NO_GO**. `--require-ready` rejects open gates. Configuration booleans, synthetic tests and artifact presence do not close them. Required remaining evidence includes actual business/brand/domain/GitHub governance, licensed market-data permissions/calendars and credentials, counsel-approved policies/retention, processor/tax/prices/portal acceptance, purchased production infrastructure and credential conformance, verified sender and monitored support/security coverage, browser/accessibility review, managed recovery/rollback/alerts, license/IP review and community/beta observation.

P14 is the final Phase 1 milestone. Next is resolving those recorded release gates and executing the missing manual/real-provider acceptance. Phase 2 livestreaming, rooms, scanners, broker integration and creator payouts remain deferred. Local engineering and the evidence/report deliverables are complete; the unexecuted external/manual acceptance remains explicitly blocked. No production launch is authorized by this record.
