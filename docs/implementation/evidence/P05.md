# P05 instrument catalog and market-data adapter evidence

Date: October 20, 2026. Requirements: REQ-006, REQ-030, REQ-032. Acceptance: AC-006 and the P05 portions of AC-030/AC-032. Status: implemented locally; automated checks pass. Rendered browser acceptance and actual commercial supplier conformance remain open.

## Scope and evidence boundaries

The milestone covers reference catalog/search/detail, actual option and dated futures contract selection, source/as-of/delay/freshness/use-rights envelopes, session calendars, independent capability enforcement and administrative disable-new-publishing controls while preserving history. P06 owns chart rendering and P07 owns drawings; later milestones own draft publication and community feeds. No Phase 2 features are included.

Parallel implementation used three cheaper agents for provider/domain, API/persistence/contracts and CSS-only web surfaces, with root integration and execution of acceptance checks. A separate bounded read-only review identified reference-data, permission and pagination defects; those were corrected and rechecked. Review is supplementary evidence, not a substitute for the executed checks below. Existing identity/media behavior and immutable migrations were preserved.

Local data is synthetic and must be visibly labeled Demo data. No commercial data credentials or signed stock/options/futures agreements have been supplied. A tested supplier protocol boundary does not mean the actual supplier account, exchange coverage, redistribution, retention or export license has been approved.

## Delivered behavior

- PostgreSQL reference lookup, filters, keyset pagination, contract detail and immutable metadata versions across stocks, standard equity/ETF options and dated ES/MES/NQ/MNQ futures. Seed data now contains 21 explicitly synthetic catalog records: one underlying, 12 option contracts across two expirations and eight futures contracts across two months. Original fixture identities and metadata remain. Incorrect original December futures expiration metadata is visibly corrected through version 2 rather than overwritten.
- Actual catalog contract selection for long calls/puts and bull/bear call/put verticals. Server validation checks every leg and underlying, current enabled state, expiry, metadata, freshness and rights; enforces same underlying/expiry/type, equal quantities, strike order and sides; and computes debit/credit and width using decimal-safe bid/ask values. Missing Greeks and unsupported strategies are not fabricated.
- Replaceable typed MarketDataPort with synthetic and Databento Historical protocol implementations. Responses carry provider, as-of time, delay, freshness and permitted uses. Five bar intervals, paginated results, UTC timestamps, session calendars, DST, holidays, early closes and futures overnight sessions are covered. Synthetic calendars are explicitly illustrative, not authoritative exchange calendars.
- The supplier boundary uses injected HTTP transport, documented form requests/JSONL and actual BBO fields, explicit symbol/metadata mappings, bounded responses/timeouts and transient retries. Session-aware 1h/1d aggregation uses approved minute data and authoritative session boundaries, preserves exact volume and withholds incomplete transport-boundary groups. Malformed prices, future timestamps and incomplete quotes fail explicitly. No real supplier request was made.
- Separate public/member display, retained bars/snapshots, image and export capabilities are enforced on the server. Active restrictions cannot be overridden by an extra permissive row. Display denial returns 403; an allowed provider outage returns 503. Production rejects synthetic mode, incomplete mappings/calendars, unsupported datasets/schemas and unapproved use rights. Fixture grants are never evidence of an actual license.
- Administrator catalog/data views and reasoned enable/disable actions require the administrator role, recent MFA, CSRF and idempotency. Actions return canonical audit receipts; replay is stable and conflicting reuse fails. Disabling prevents new publishing eligibility while retained metadata/history remains accessible where rights permit. P08 will consume this eligibility boundary for actual publications.
- Public `/instruments` and `/instruments/[id]`, member `/app/explore`, and staff `/admin/instruments` and `/admin/data` use the API. Actual option/futures selectors, metadata history, expired/near-expiry notices, source/demo/capability states and explicit unavailable states are implemented. Authenticated requests derive their audience from the server session. Client-safe formatting is separated from server API access. Authored UI uses CSS Modules, shared tokens and Phosphor; no Tailwind or new styling framework was introduced.

Canonical OpenAPI and generated clients now contain **125 operations and 106 schemas**. Migration `202610200010_provider_instrument_mapping` adds immutable instrument/version supplier mappings with controlled revocation, bringing the schema to **52 Prisma models and ten migrations**. Applied SQL history was not edited. No external package was added; the web app now declares the existing internal contracts workspace dependency. API-only supplier configuration is documented in `.env.example`; existing local secrets were not changed.

## Defects corrected during acceptance

Protocol/domain review corrected futures expirations, DST/session boundaries, real BBO parsing, decimal/volume preservation, same-scope restriction composition, missing underlying/leg checks and hourly/daily pagination. API integration corrected canonical status codes, calendar venue projection, query validation and restricted-record pagination. Web integration corrected server-only API imports reaching client components, CSS paths, authenticated audience selection, strike/leg ordering and stale selectors. The earlier exact-nine seed assertion was changed to preserve every original fixture identity while allowing the expanded catalog.

Initial failed checks and a transient development restart are not counted as passes. The final stable checks above passed after correction. The bounded review did not establish production supplier conformance or rendered interaction quality.

## Browser limitation

The supported browser tool was retried for `http://localhost:3000` during P05 and returned a saved permission/security-policy denial. No alternate/headless browser workaround was used. Rendered visual, responsive, keyboard, screen-reader and interaction acceptance remains unverified; HTTP/SSR checks do not replace it.
