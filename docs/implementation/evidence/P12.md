Date: October 20, 2026. Requirements REQ-001 and REQ-021; acceptance AC-001 and AC-021. Local implementation and automated acceptance are complete. Rendered visual/keyboard acceptance and external processor acceptance remain open. No paid launch, real purchase, processor approval, deployment, Git commit or PR is claimed.

## Scope and decisions

P12 implements monthly/annual hosted checkout, account billing/portal/invoices, signed provider events and current-state reconciliation, bounded access/grace/cancellation/downgrade, reasoned administrator support and a persistent synthetic local processor. CSS/CSS Modules and Phosphor remain the authored UI standard. See [ADR 0023](../../adr/0023-billing-provider-truth-and-recovery.md).

- The server maps Pro to $29 monthly or $290 annually. Verified identity, current terms, owner authorization, CSRF and stable command identity protect checkout and portal creation. An open or uncertain checkout is resumable and prevents a second purchase. Checkout success/cancellation URLs never grant Pro; the return screen reports current server truth. Price cards retain their selected billing intent through authentication.
- `/app/billing` shows plan, limits/usage, current subscription, paid-through/grace/cancellation state, invoices, portal and interrupted-checkout recovery. `/admin/billing` permits reasoned refund, period-end cancellation and reconciliation with current administrator role and recent MFA. Refund and cancellation are separate actions; staff receive immutable audit receipts and cannot edit Pro flags. Unavailable provider, stale/replayed command, unsafe URL and authorization failures are explicit API/UI states.
- Raw request bytes are verified before parsing, with bounded signature timestamps and mode/account isolation. Events are deduplicated but reconcile current processor state rather than replaying stale event status. A separately authenticated worker sweep recovers failed events and uncertain operations; forged, expired and reused internal credentials are rejected. Provider adapters remain replaceable.
- Current provider/account/mode and bounded validity apply to every API and worker entitlement read. Active access and paid-through cancellation expire at their actual period; a failed renewal receives one fixed 72-hour first-failure grace, which repeated events cannot extend. Unpaid state returns Free. Downgrade preserves records, owner edits and raw personal export, while new additions and Pro analytical exports remain gated. Historical personas can grant access only in the original local fake/test scope.
- Provider writes are preceded by durable operations. Refunds preserve their resolved amount, command key and provider operation evidence across lost acknowledgments. Recovery proves prior mutations before retrying and never blindly repeats an operation outside the provider idempotency window. Concurrent synthetic refunds lock their invoice within the same PostgreSQL transaction and cannot exceed its paid amount.
- Separate persistent synthetic processor records drive explicit owner-confirmed local checkout/portal pages. No browser parameter or fixture array activates Pro. Stripe uses native server fetch/crypto with API version `2025-06-30.basil`, validated fixed price/product/currency/interval, scoped resource metadata and safe hosted URLs. All state reads have a shared deadline and bounded pagination/concurrency. Fake mode and unapproved live configuration fail closed in production.
- Reconciled conversion/churn uses P11's explicit-consent boundary. Mandatory billing notices cover subscription, invoice, refund and dispute changes. Staff billing DTOs omit private journal content and payment credentials.

## Repairs and verification limits

Review corrected cross-provider legacy entitlement reads, provider/account namespace and validity consistency, uncertain operation evidence, cancellation paid-through calculation, concurrent synthetic refund serialization, safe processor redirects and resumable checkout handling. An early live driver reused a session revoked by a role change: the driver now creates separate valid non-MFA and recent-MFA staff sessions after the role grant; authorization behavior was preserved. A native Node TSX test import failed in an early isolated run; the test now uses the already-installed `tsx` API, without a new loader dependency. Initial failed runs are not represented as final passes.

P11 regression first failed with `SNAPSHOT_READY_HYDRATE` and earlier one-use claim conflicts. The optional Next debug channel uses the development HMR socket; blocking the whole stream stalled hydration. An experiment disabling that channel completed capture but failed the session-secrecy HTML assertion, so it was reverted. The final worker transport permits only Next's pinned binary React debug frame from the exact configured HMR origin/path, discards textual hot updates/reloads and client traffic, and keeps other sockets inert. Close events cannot start the development reconnect/reload loop. Safe renderer stage codes expose no signed URL or private content. The P12 session-secrecy and P11/P09 connected regressions passed on that final policy; signed render claims remain single-use and capture readiness/callback ownership remains atomic. Builds, type generation and production-boundary harnesses must finish before trusted capture begins; restart web and wait for `/health` afterward. A Next upgrade must repeat both capture and session-secrecy checks.

After the final 347-test isolated run, typecheck, optimized build and production-boundary harness, web was restarted and `/health` checked. P12 billing/session-secrecy, P11 trusted capture/notifications/email, and all nine local smoke checks passed again without intervening source edits or builds. No final automated failures remain.

The supported in-app browser rejected localhost under a saved origin permission. No alternate browser, raw CDP or headless UI-inspection workaround was used. Rendered visual, focus/keyboard and interactive checkout/portal acceptance remain G08/G12 gates. Existing product-owned trusted capture is exercised by publication acceptance and does not establish manual visual review. The checkout has no Git repository or remote, so no commit, PR or remote CI is claimed.
