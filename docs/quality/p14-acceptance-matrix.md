# P14 acceptance matrix

This matrix maps the 32 acceptance scenarios to existing test suites and milestone evidence. It is an index of coverage, not a declaration that every scenario passed. The P01–P13 evidence records contain historical local outcomes. The final P14 clean-database run passed 372 automated tests with none failed/skipped, and connected P04–P13 drivers passed again. Executed commands, measured local drills and limitations are in [P14 evidence](../implementation/evidence/P14.md). These results do not close every scenario.

“Automated evidence” identifies relevant suites and what they exercise, not full scenario closure. “Remaining evidence” calls out material gaps, especially rendered/manual browser work and provider, legal, operational, or production gates. See the [P14 accessibility source review](p14-accessibility-matrix.md) for static findings and the manual browser matrix, which remains not run. The release status is [NO_GO](../implementation/p14-release-status.json).

## P14 coverage and evidence state

P14 suites passed for signed ingress, exact request bytes, shared replay protection, provider webhook signatures, email suppression, R2 protocol bounds/private authorization and production refusal. The real database suite, connected drivers, local recovery/load/roles, image builds, optimized HTTP CSP and outage/restart results are recorded in the linked P14 evidence. The source scan is heuristic; platform license metadata gaps and full container/business-rights review remain open.

Automated tests and local service drills cannot close the manual browser matrix or external release gates. Current manual browser checks remain unrun, provider/legal/commercial approvals remain separate, and production recovery objectives require production-grade evidence. A local candidate must not be described as released until those gates are resolved.
