# ADR 0015: Executable local identity, profiles and private media

Date: October 20, 2026. Status: engineering implementation; local acceptance evidence in [P04](../implementation/evidence/P04.md). Extends [0007](0007-oidc-sessions.md), [0008](0008-jobs-objects-email.md) and [0014](0014-preview-shell-contact-intent.md).

## Context

P04 replaces account/profile previews with a real identity and avatar vertical slice. Browser and container clients must validate the same issuer. Provider credentials must stay outside application records. Uploads cannot become public merely because a processing job finished. Existing migration history and CSS-only styling remain binding.

## Decision

Use openid-client **6.8.8** and jose **6.2.12** for discovery, code exchange, signed claims and logout verification. jose 6.2.13 was newly published on October 20 and rejected by the existing minimum-release-age policy; choose the mature exact patch without weakening that policy. Sharp **0.35.5** processes local images. These are project dependencies, with no host toolchain changes.

Keycloak uses the same `http://auth.localhost:8080/realms/options-trade-ideas` issuer from the browser and Docker identity network. The confidential client has an exact callback, S256 PKCE and no application password grant. Local Mailpit handles verification/recovery messages. Idempotent configuration preserves existing provider users; separately generated synthetic personas live only in ignored mode-0600 local storage. Provider registration, verification, recovery and MFA use themed provider pages.

Bind each authorization transaction to its own HttpOnly cookie, a hashed state and encrypted verifier/nonce. Validate issuer, audience, nonce, time and signature before account mapping. Exchange successful identity for a random opaque application cookie; only its hash enters the session table. Server roles, verification/onboarding state, idle/absolute expiry, exact origin and session-derived CSRF protect commands. Signed ACR 2 plus recent signed authentication time govern MFA step-up. Privilege/account-state changes revoke sessions using additive database triggers. Signed backchannel logout is replay-protected. Credential-change enforcement also requires the application-owned Keycloak event-listener SPI: ordinary provider password/TOTP forms alone only optionally sign out other sessions, and account credential removal does not. The local Keycloak image compiles that small provider against the exact pinned server jars in a separate pinned JDK build stage; no JDK is installed on the Mac. Required-action theme notices explain session invalidation. Configuration refuses a realm missing the listener. Failure semantics and actual provider acceptance are recorded in P04 evidence, not inferred from a hidden form field. Incoming development web request logging is disabled to avoid logging callback query credentials.

Keep private identity separate from public profile projections. Handles are reserved/unique with one-year historical redirects and permanent reservation of old handles to prevent reassignment. A profile row lock serializes the one-change-per-30-days rule, with an explicit next-allowed UTC timestamp. Optimistic revisions protect edits. Terms and declaration acceptances are stored as versioned rows. Plan intent is navigation only; paid entitlement remains server-derived and billing belongs to P12.

Credential revocation sends a signed subject-only logout to every enabled OIDC client designated by `trading-community.credential-revocation=true`, independently of any provider SID or client-session membership. App sessions can outlive provider SSO, so enumerating provider sessions alone is insufficient. Each designated target must have a backchannel URL; no target, missing URLs or failed delivery marks the provider transaction rollback-only. The relying party accepts subject-only events (`backchannel.logout.session.required=false`). Password/OTP, email/profile/verification changes and admin credential changes are covered; all root user representation updates conservatively revoke because event representations omit credential values. Unexpected failures also mark rollback explicitly because Keycloak catches listener exceptions. Public subject mapping is required; pairwise subjects and federated adapters need additional validation before enabling them. The live drill proved both zero-SSO and orphan-SID revocation, plus rollback during API unavailability.

Native Keycloak action redirects can still report `kc_action_status=success` when this listener marks a transaction rollback-only. Persisted credentials and app-session access, rather than that redirect, determine acceptance. Provider failure messaging remains a production UI review gate. Eventless `disable-credential-types` requires explicit operator revocation before use.

A filesystem StoragePort stores quarantined and processed objects outside static web roots. Owner-bound upload intent constrains MIME, byte size and expiry. Completion commits a durable outbox event; a separate pg-boss worker decodes and re-encodes to bounded WebP, removing metadata. Malformed input is terminally rejected; transient processing has bounded retries, and abandoned objects are swept. Owner access is authorized on each request. A processed avatar becomes publicly readable only while attached to an active public profile; removal immediately denies anonymous reads. All media delivery is `private, no-store` to prevent stale public caching after removal. Attachments and chart snapshots retain owner access until their later publication milestone supplies a public authorization rule.

Migration 008 adds media lifecycle metadata, logout replay and policy acceptance. Migration 009 revokes sessions on role/account security changes. No earlier migration is edited. OpenAPI adds standard optional callback parameters, historical-profile redirects and explicit session MFA state; generated contracts remain authoritative.

## Consequences and verification

The local identity/media flow now crosses the actual provider, API, PostgreSQL, outbox, worker and storage boundaries. Automated protocol tests are separate from rendered browser acceptance. The saved browser-tool permission still blocks localhost; no alternate browser or headless workaround is used. Production identity hardening, approved policy text, sender domains, supplier contracts, deployment credentials and complete SBOM remain release gates. This decision neither approves branding nor authorizes deployment.

Actual executed checks and remaining limitations belong in the milestone evidence.

Local Next reverse-proxy traffic currently shares the internal proxy address for API IP buckets. Per-account write limits remain distinct. Before production, P14 must configure and test trusted ingress/client-IP derivation for public/login limits without trusting arbitrary forwarded headers. No unrestricted Express trust-proxy setting is introduced.
