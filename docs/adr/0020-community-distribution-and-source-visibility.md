# ADR 0020: Community distribution and source visibility

Date: October 20, 2026. Status: engineering implementation for P09; executed checks are recorded separately in [P09 evidence](../implementation/evidence/P09.md).

## Context

REQ-014–REQ-017 and REQ-025 require public discussion and distribution without duplicating trades or allowing public derivatives to outlive source permissions. Personal follows, bookmarks and mutes must not become public profile data or let an author suppress criticism. External shares must preserve attribution and use current image-export permission.

## Decision

- Use PostgreSQL `simple` full-text indexes over current public title/thesis and public author display name/handle. Discover, Following and separately labeled Editorial use newest timestamp/ID/repost-ID keysets. Cursors bind normalized query/filter/feed/viewer context. The only supported sort is Newest. Editorial requires a current manual selection and completeness/follow-up criteria; no subscription or high-win-rate boost is introduced.
- Preserve PostgreSQL's six fractional timestamp digits in all community and feed cursors; public display timestamps can remain millisecond ISO strings. Serializing a database key through JavaScript Date would truncate microseconds and skip or repeat same-millisecond records. SQL cursor projections and strict decoding retain the original ordering precision.
- A repost is an attributed distribution record, unique while active for a member/source. It never creates a publication, position, fill time or outcome. Reactions and discussion always resolve to the original. Personal mute affects feed distribution, including muted source/reposter, and never removes public criticism from a publication thread. Notification delivery remains P11.
- Resolve bounded mentions to existing member identities when a plain-text comment is written. Store direct reply target and root separately; render two levels while retaining the target. Revision-protected edits and tombstone deletion preserve thread shape and retain prior text in restricted history. Suppressed or inactive-author content uses neutral tombstones. Reports persist an owner-only receipt; staff moderation/appeals remain P13.
- Apply verified/onboarded session, CSRF/origin and server object authorization to writes. Add comment/report database-backed limits to the existing account-wide limit. Idempotent command replay consumes no extra command quota, but a stored public receipt is reauthorized before returning it. Optional personal public reads distinguish an absent session from a supplied invalid one; the latter fails closed. Personal response fields and public source projections use no-store responses.
- Recheck source visibility, active author, current committed version and data capabilities for feeds, search, bookmarks, reposts, public metadata and images. No persistent derivative cache is introduced. Current version is checked again after source authorization before a selected feed/discovery row is emitted. Public disclosure includes the practical limitation that downloaded files and external social caches cannot be recalled.
- Share menus load canonical server-selected metadata, use encoded public links, and open external destinations only on explicit clicks. Native share is invoked directly within the user gesture after metadata is ready. Clipboard denial offers a selectable canonical-link fallback. No third-party widget or automated posting is added.
- Keep the original 1200×760 immutable chart response unchanged. Licensed `download=true` exports append a 112px footer with original author, original publication UTC date, strategy and actual instrument/month. Existing chart/source/delay/TradingView notices remain above it. Image export rechecks independent export permission; text/link sharing remains available when permitted.
- Generate sixteen dynamic discovery shards by stable UUID prefix, plus a sitemap index. Each public discovery page authorizes current records; a version-pointer change skips that candidate. Bounded traversal stops rather than emitting a partial stale file if authorization or pagination fails. Profiles/instruments/publications are discoverable only within their current public conditions. Preview discovery is empty and private/historical/preview routes remain noindex. This design is not a completed P14 load/performance assessment.

## Consequences

Migration 014 adds resolved mentions, retained comment edit history, report detail, partial follow uniqueness and full-text/retrieval indexes. Earlier applied migrations remain unchanged. Four additive read operations expose viewer state and authorized discovery; generated contracts total 129 operations and 111 named schemas. No new external dependency, service purchase or deployment is required. CSS Modules/plain CSS and existing Phosphor assets remain the UI standard. Browser clipboard/native-share, visual and accessibility acceptance require the supported browser surface; a policy denial remains a recorded gate rather than a simulated pass.
