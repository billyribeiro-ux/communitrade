# ADR 0025: Production boundaries, recovery and release evidence

Date: October 22, 2026. Status: engineering implementation; production acceptance remains gated. Implements REQ-025, REQ-026, REQ-027, REQ-028, REQ-030 and REQ-031. See [P14 prompt](../prompts/P14-integration-release.md), [release register](../implementation/p14-release-status.json) and [external gates](../handoff/dependencies-and-release-gates.md).

## Decision

Production runs the existing pinned Next frontend on Vercel with a fixed backend origin. The server route handler preserves raw bytes and cookies and signs the method, complete path/query, body hash, timestamp, nonce and provider-derived client address. Only the Vercel runtime's overwritten address header is accepted, with explicit platform configuration. Generic forwarded headers and browser-supplied signatures cannot choose a rate-limit principal. Server rendering uses a separate signed service principal. The API verifies signatures and consumes nonces atomically in PostgreSQL across replicas before replacing its socket address. Missing configuration or unavailable nonce storage fails closed. Exact health and independently authenticated provider/internal-worker endpoints retain their existing boundaries, including OIDC backchannel logout.

Private R2 objects use the existing replaceable storage ports, native SigV4 signing, strict account/bucket/key grammar, bounded bytes/deadlines and conditional immutable writes. Downloads still authorize the owner or current public attachment on the server; no public bucket or presigned bearer download is introduced. Upload quarantine remains private. Media uploads are limited to 2 MiB, trusted processed snapshots to 4 MiB, and personal archives to 50 MiB. API and worker use the same private bucket configuration. Real account/bucket permissions and lifecycle acceptance require actual credentials and supplier evidence.

Production email remains authenticated TLS SMTP. The Resend endpoint verifies original bytes using its Svix signing format and a bounded timestamp, validates the configured sender, and deduplicates event IDs transactionally. A permanently bounced or complained recipient receives account suppression and a purpose-separated keyed address digest, including anonymous support recipients. Transient/unknown bounce classes cannot permanently suppress a recipient. Replay records contain only type/hash/time/ID, expire after 30 days, and never retain provider subjects or message bodies. Address suppression uses the stable privacy key with a separate purpose prefix and is backed up with operational suppression data. No plaintext address is added to this ledger. Successful SMTP handoff is distinct from final delivery; uncertain acknowledgments retain the existing quarantine behavior.

Production startup rejects synthetic data, local objects, fake billing, weak/shared keys, insecure transport and missing reviewed operational configuration. Policy records remain drafts until actual review artifacts are supplied. CSP uses a fresh document nonce, restricts script sources without production eval, and forbids embedding/objects. CSS Modules remain the authored styling standard; inline style attributes remain permitted for rendering-library geometry. HSTS is enabled only after domain/HTTPS verification. Nonces require dynamic rendering; actual browser acceptance remains a separate check.

Database-outage rehearsal also requires safe idle-pool errors and a worker that receives termination signals directly. The API emits a fixed event without serializing the failed client. Local Compose runs the worker through Node/tsx directly with a 30-second grace period; source edits require an explicit worker restart. Production images already run Node directly.

Deployment artifacts are preparation, not provisioning authorization. Runtime, migration, backup and identity credentials are separate; a single reviewed migration actor applies compatible additive SQL before runtime rollout. Rollback uses an immutable application image compatible with the existing schema, or a reviewed forward fix. Database recovery targets a separate instance, validates private objects and imports the newest independent deletion ledger before traffic returns. Local generated-database drills never reset application/identity volumes.

The public feed orders and limits original/repost branches using their exact microsecond cursor predicates before merging them. Card aggregates operate only on the bounded page. Identical reference-rights checks are reused only within that request, and a final batch rechecks every candidate author, profile, source visibility, current version and mute. Revocation never relies on a persistent permission cache. This keeps the representative feed within its ordinary API target without weakening authorization or changing page size.

An explicit release report tracks all twelve gates and every acceptance scenario. Synthetic protocol tests, local timings, configuration booleans and artifact existence cannot establish legal approval, provider conformance, monitored staffing, WCAG conformance or production recovery objectives. Open gates result in NO_GO. No tool automatically deploys or charges users.

## October 22 GitHub security follow-through

Native CodeQL analysis of the published candidate identified ten findings. Keep the existing server-selected API destination and validated media keys, and strengthen their enforcement with authority-preserving URL component assignment and independently resolved storage-root confinement. Replace ambiguous numeric-regex branches with disjoint alternatives and decode provider form entities in one pass through the shared local test helper. Regression tests cover authority/path escapes, sibling-file preservation, hostile long numeric text under a child-process timeout, and entity-layer semantics. These are boundary hardening within P14, with no new providers, permissions, data rights or Phase 2 scope. Scanner execution and reviewed findings are evidence, not certification; fixes remain subject to independent review and repeated scans.
