# Contract validation and generation

`contracts/openapi.json` and `contracts/chart-state.schema.json` are the canonical machine contracts. Run `pnpm --filter @trading/contracts generate` after changing either file; this emits the typed path/schema surface and the runtime operation manifest. `pnpm --filter @trading/contracts check` validates OpenAPI 3.1 and local references, compiles every component schema and the full chart schema with JSON Schema 2020-12, exercises representative request validation, and checks the generated surface against the canonical files.

Runtime request validation uses the generated operation manifest, checks path/query/header/body fields, enforces required values and bounds, and rejects undeclared properties. It validates values as supplied and leaves normalization to the transport or domain layer. Decimal values remain strings. `ContractValidationError` includes field paths only; callers may map it to the API's RFC problem shape. The generated fetch client uses `cache: no-store`, omits cookies for public operations, uses same-origin credentials for protected operations, and adds CSRF only for operations declaring that header. It keeps binary image uploads, form-encoded OIDC logout requests, and binary download responses in their declared transports. Authorization and private-resource existence decisions remain server responsibilities.

The generator intentionally uses JSON Schema definitions from the source contract instead of a compiler-version-sensitive TypeScript compiler API. Generated files are checked byte-for-byte so source and generated contracts cannot drift unnoticed.
